# ISSUE TRACKER

All problems, errors, bad recommendations, failures, rule deviations, degradation events, saturation entries, word-sense separations, and anything else of that kind (EVERY LIST IS OPEN). Investigated on first occurrence — and what investigation means depends on what the entry reports (PROMPT.md §8 ISSUE TRACKER): entries about the game, a method, a recommendation or a failure are investigated for root cause; entries reporting this system's own state are investigated by comparison against entries sharing the category/pattern and against patterns flagged in recent digests, then judged for whether the pattern bears on advice. Saturation entries are exempt from investigate-on-first-occurrence to prevent administrative death-spirals.

Format: SCHEMA.md §2.4.

### ISS-002 — Shell-role network egress is an allowlist, not open internet  [OPEN — environmental, not fixable from inside]
opened: 2026-09-27T17:04Z | kind: environment/capability
report: `curl` from the shell returns HTTP 000 for every DLS-relevant host (FTG, SakibPro, Play, App Store, Reddit, YouTube, APKPure, APKMirror, Wikipedia, DuckDuckGo, Wayback, jsDelivr, Maven) and for objects.githubusercontent.com / raw.githubusercontent.com, while github.com, api.github.com, codeload.github.com and pypi.org return 200.
investigation: Root cause = sandbox egress filtering, a property of the environment rather than of any source (apt is also blocked, so no tooling can be added at OS level). Directly probed with a desktop User-Agent and a 10 s timeout; the same host (firsttouchgames.com) that returned 000 from the shell was fetched successfully by the page-render role in the same turn, which proves the barrier is the shell's egress path and not the source. Bypass attempts made and their results: page-render = WORKS (the primary bypass); discovery-search = WORKS; custom UA = no effect on the blocked hosts; jina reader proxy = blocked; GitHub API contents route = WORKS (base64 file contents, bypassing raw.githubusercontent); codeload tarballs = WORKS (bypasses repo-clone needs); GitHub release assets = FAIL (objects.githubusercontent unreachable); pip/PyPI = WORKS (bypasses apt for pure-Python tooling).
resolution: Recorded once as a network-access gap in CAPABILITY_INVENTORY.md §4 with the classes of source affected, per PROMPT.md §5 WALL-BREAKING (report once per cause, not once per source). Standing consequence enforced repo-wide: no source may be declared a wall source on the strength of a shell 000 — page-render and discovery-search must be attempted and failed first. Remaining genuine gap: binary acquisition (APK/ZIP/image bytes) is limited to codeload, GitHub API contents, PyPI, and image_search. Bears on advice: yes — it constrains Step 2's datamining depth, so it is carried in the handoff and will be surfaced at first contact rather than discovered later.

### ISS-005 — Self-detected tier defect: first-party single-source claims were recorded at High Confidence  [RESOLVED — correction applied; design tension escalated as a PROPOSED amendment]
opened: 2026-09-27T17:40Z | kind: degradation (own output) + rule-tension
report: While writing KB claims from FTG's own Play Store listing and site (S-0002, S-0011, S-0012), several claims were tiered **High Confidence** on the reasoning that a first-party document with a checkable origin is strong evidence. Mechanism 5 requires **2 independent sources** for High Confidence. Two surfaces of one origin (FTG's site link + FTG's store listing) are one source; an aggregator echo (appbrain) is not a second. The tier assignments therefore violated the gate.
investigation: Root cause = treating origin quality as a substitute for the count gate — precisely the failure Mechanism 5's "WHAT THE COUNT DOES AND DOES NOT PROVE" warns about from the opposite direction, and the reason the prompt says a claim being carried by the standing of its source is a defect. Caught by re-reading the gate while writing the second batch of claims (Mechanism 2 Skeptic applied at promotion). Underlying design tension is real and is not the agent's to resolve: Mechanism 5 states both that counts are the gate and that "the count is never what makes a claim true", so a claim read directly out of a first-party document — the most checkable class of evidence there is — cannot exceed Speculative unless a second party happens to have extracted it independently. Precedence applied: rung 3 (the more exhaustive reading wins) plus A CONSERVATIVE SIGNAL (the reading that holds work open longer and demands more evidence) → the count gate governs.
resolution: All affected claims downgraded to Speculative with `origin: DIRECT` recorded and an explicit promotion path (a second source independent by author, platform, or method of extraction — e.g. an APK manifest against a store listing). Interpretation written into `kb/README.md` as a TIER POLICY NOTE so no later session repeats the error. Logged as a REVISION (register entry R-0001) and as a SKEPTIC CHALLENGE. Design tension escalated to `prompt_versions/CHANGELOG.md` as a PROPOSED amendment — the rule keeps being followed as written until the user adopts anything (WHO MAY CHANGE THIS FILE).
saturation_exempt: false

### ISS-007 — Environment reset replaced local git history mid-session; recovery rule adopted  [RESOLVED — rule standing]
opened: 2026-09-27T21:55Z | kind: environment / process integrity
report: Between turns 7 and 8 the workspace was re-cloned: `.git` held only the initial commit plus the new turn's commit, the branch sat at the base commit `fb9a2c0`, and the repository git identity had reverted to the clone default, while the working tree carried the snapshotted turn-7 files. The turn-8 push was rejected because the local chain diverged from the remote tip `ff5c247`.
investigation: Investigated per PROMPT.md §8 for entries reporting this system's own state: the reflog (clone → checkout → commit, nothing else) established a fresh clone rather than any local history operation; the tree comparison (turn-8 commit's tree equal to remote tip plus the turn's changes) established that no CONTENT was lost or corrupted — only ancestry and identity. The remote held all prior turns throughout; the platform snapshot held the files. The failure mode is environmental, not procedural: snapshots persist files, not `.git` history, so any workspace restoration can silently divorce the working tree from its history.
resolution: Recovered by fetch + `reset --soft` to the remote tip + re-commit of the same tree and message (`e5320e5`), push, verification of remote tip and clean status. Standing rule adopted and written into HANDOFF.md and OPERATIONAL_RULES.md: verify local HEAD against the remote tip at the start of every turn before committing; on divergence caused by a reset, recover with fetch + reset --soft, never push a diverged chain, never force-push. Saturation: the rule makes recurrence detectable at turn start rather than at push time, which is where it cost this session a rejected push and an investigation.
